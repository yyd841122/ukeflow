## 问题

曲谱获取主渠道此前押在 PDF 像素识别上(ADR-0009/0010),57/59a/61 三方互证其难度
(事件 F1 ≈ 0.16-0.19)。用户实证了一条确定性渠道:谱站(alphaTab 渲染器)的**整页
渲染 HTML**——纯矢量几何(text/rect/path),无嵌入语义数据但坐标精确,解码不是猜。
样本两首已验证可读可转:

- `~/ukeflow-sources/vector-pages/tiankongzhicheng*.html` — 天空之城(久石让/小埋 编谱),
  指弹 TAB,key=C 4/4,♩=80,12 系统,Part A 分段;
- `~/ukeflow-sources/vector-pages/xuancaohua*.html` — 萱草花(张小斐/靠谱ukulele-Louise 编谱),
  弹唱谱,key=C **3/4**,♩=80,33 小节 6 系统,主歌@1/副歌@17,含和弦指法图、
  简谱旋律行(带八度点)、两段歌词、节奏带、反复记号。

注意:原始文件 UTF-16LE CRLF(`*-orig-utf16.html` 为原字节),UTF-8 副本已转好。
仓库外产物目录 `~/ukeflow-sources/vector-pages/`,pytest 用 skip-if-missing 纪律引用。

## 决策(grill 终局)

1. **渠道分工**:谱站搜索/下载归**外部独立项目**(不在本仓库);本 App 只认
   「收件目录」里的矢量谱页文件。接口契约:**一个 HTML 文件 = 一首曲 = 一个完整
   渲染块(`.at-surface`)**;文件名随意,歌名/署名/拍号/速度全部从谱面内容读。
2. **入库触发 = 界面「检测」按钮手动**(用户 Q13 定,不做后台扫描/开App即扫);
   按文件指纹记账,不重不漏。
3. **矢量源信任等级**(修订 ADR-0009「校对台人工逐位确认」纪律,仅限矢量源;
   PDF 线纪律不变):解码输出过**体检闸**(每小节拍长闭合/音域界内/和弦指法图
   对照/来历不明符号显式)→ 全绿自动入库,红旗只列疑点待用户确认;原始 HTML
   永久存档,随时回查。
4. **拍号通用化必须做**(用户 Q8 定:「根据歌曲来确定,不能只有4拍」)——解除
   assets/charts/README「v1 仅 4/4」约束,萱草花 3/4 才能弹唱跟练。
5. **PDF 识谱线搁置**(用户 Q11 定):工单 60/61/62 挂起(ADR-0010 追记四),
   遇「网上无源」的歌再议重启,须单独决策。
6. **施工顺序**(用户 Q12 + 复查定):先把**这 2 首**导入弹起来(票01→02→03),
   确定「可弹」之后再做通用化(票04 收件目录/检测按钮/Dart 解析器移植)。

## 边界

- 下载器项目不属于本仓库;它坏了只影响「有新谱可下」,不影响解析正确性。
- 弹唱谱型 HTML 在票04 落地前若出现在收件流程里,检出并标记「待支持」,不静默丢弃。
- 歌词自动提取自用户手动保存的授权副本,纯自用边界内(票03 落地时与
  assets/charts/README「歌词由维护者录入」惯例对齐:转录主体仍是维护者自己的保存件)。
