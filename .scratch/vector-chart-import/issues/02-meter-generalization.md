# 02: 拍号通用化(文本谱+弹唱引擎,解除「仅 4/4」)

**Status:** ready-for-agent

**Blocked by:** 无

**What to build:** 让 App 能按谱面拍号数拍(3/4 为首个目标,萱草花;设计上不写死
4/4 也不写死 3/4)。范围:

1. **文本谱头域**:ChordPro 头加拍号(如 `{meter: 3/4}`);`chord_pro 0.8.0` 解析
   与谱面校验面放宽——缺省仍按 4/4(既有 24 首 builtin 零改动),显式非 4/4 合法;
2. **拍格与时间轴**:节拍网格、预备数拍(固定 4 拍的约定重审:按拍号给整小节
   数拍?)、动作事件时间轴的整小节语义全部按 beatsPerMeasure 参数化重审;
3. **节奏型库**:现仅 4/4 八分槽+上下扫(memory/ADR-0010 追记三口径),补 3/4
   槽位;萱草花节奏带的实际扫弦型在票03 解码后回填;
4. **跟练 UI/评分**:按拍显示、小节高亮、评分窗口凡有 4 硬编码处逐点清查;
5. **ADR 附随**:拍号进文本谱头域是格式决策,随本票立 ADR(或 ADR-0002 追记,
   实现时按三条件判断)。

**已证约束(2026-11-05 考古):** assets/charts/README 明载「demo 的《奇异恩典》为
3/4 拍未迁(v1 仅 4/4,谱面校验会显式拒绝)」;用户拍板「根据歌曲来确定,不能
只有4拍,这个逻辑必须更改」(Q8)。

**验收:**

1. 合成 3/4 文本谱过校验、4/4 既有谱零回归(check.sh 全闸绿,builtin 资产测试
   逐首不变);
2. 3/4 跟练:预备数拍/节拍高亮/小节推进按 3 拍走,真机演示(可与票03 合并
   真机验收);
3. 迁移《奇异恩典》为 3/4 的路径确认可行(不必本票完成,证明校验不再拒收即可)。

**Non-goals:** 变拍(单谱中途换拍号)另议,不进本票;萱草花数据本身(票03);
指弹谱侧拍号(识谱源 meter 本就参数化,物化端如遇 4 硬编码顺带清,但不扩 scope)。
