**Status:** implemented (awaiting device check)

**参照物:** 用户录屏 `/mnt/d/Desktop/天空之城.mp4`(WSL 路径)= 谱全网网页版
播放,1326×1796@30fps,157s,带原站示范音频。拆帧/抽轨命令:
`ffmpeg -i 视频帧率1 → 帧; -vn -ac1 -ar16000 → wav`(ffmpeg 用
`/tmp/svgenv/bin/pip install imageio-ffmpeg` 的自带二进制;/tmp 会被清,

**从视频量到的基准事实(2026-11-07):**

- 第一声 3.26s;谱通量检测 308 个节奏点;间隔 0.375s(八分)/0.75s(四分)
  ——与印张节奏、♩=80 完全吻合(解码正确的又一旁证)
- 站方红线**连续平滑**移动(逐秒 x:356→455→525→693→799→962→1203),与
  声音同步(1s 采样粒度下 ±0.3s)
- 站方红线颜色 RGB(193,103,113);**弹奏染色**的原站配色待从帧取
  (已弹/当弹/未弹三态,取色点:曲中已弹小节 vs 未弹小节)

**mini-grill 结果(2026-11-07,用户逐条确认):**

1. 染色照抄原站:配色与变色范围从用户视频帧取真实值,不自创
2. 红线固定 + 内容流动(单行流水形态不变);**曲头曲尾全覆盖**:
   曲头 = 位置 0 落在播放头线上(需左侧余量,量用 Dart 视口宽算,
   **禁止 OEM innerWidth**),曲尾 = 流过最后一小节收(尾部余量已有,
   验收时核)——现状曲头未从 0 起、曲尾需复核
3. 保留起播 4 拍预备数(不跟原站默认关)
4. 点谱面跳播:这轮不做
5. 验收 = 网页版与 App 并排对比,除「整页多行 vs 单行流水」结构差异外,
   流动手感/变色/声音同步肉眼无差异

**范围:**

1. 弹奏染色:页面装载时建音符元素坐标索引(横带 svg 的 text/rect 按 x
   分列桶),帧驱动把当列/已弹元素改 fill;染色指令经 JS 桥的频率 =
   列变化率(~0.375s 一次)单发可接受,丢发由下一列重发自愈(列桶带
   序号,幂等)。配色从视频帧取样后写成常量
2. 滚动逐帧连续:16ms 原生 scrollTo 步进 → 与 rAF 同频的平滑(方案
   agent 拍板:如 16ms 内插或平台滚动动画),验收对照视频手感
3. 曲头左余量(Dart 宽度/3)+ 曲尾复核

**Non-goals:** 点选跳播、评分、整页多行结构、票07 已交付项(提示条/
双钮/节拍跟练)。

**OEM WebView 实测事实(2026-11-07,本机,WebView 97):**

- 高频 runJavaScript 会排队 jam(首几发后全丢);单发也可能被丢 →
  一切 JS 指令需幂等+重发自愈
- innerWidth 报值不可信(疑似物理像素或异常值),页面几何一律
  Dart 算好注入数字
- 3MB loadHtmlString 本机装载 ~3.4s;onPageFinished 不可靠
  (setNavigationDelegate 异步挂载赶不上首装载)→ 装载 future +
  1.5s 定时器三路就绪
- 原生 scrollTo/scrollBy(平台方法)可靠;position:fixed 图层
  滚动前不重绘、滚动后错位 → 播放头等覆盖物一律 Flutter 层画
- 横带视图 GlobalKey 单实例复用:空闲/运行两树槽重挂不重载
  (3MB 页只装一次);装载期白转圈遮罩

**验收:**

1. 并排对比网页版:流动手感/变色/同步肉眼无差异(Q5)
2. 曲头:弹奏点 0 在线上;曲尾:流过末小节收
3. 真机全链:装载转圈 → 曲头 0 落线 → 首音按拍流到线上 → 三检查点
   线位=弹奏位 → 曲末收 → 停止回闲;logcat 干净
4. flutter/pytest 全闸绿;染色有测试(列桶索引/改色指令幂等)

### 2026-11-07 实现(agent)

**视频帧取样结论(拆帧逐帧像素取证,30fps,43-47s 连拍 15 帧):**

- 站方染色是**两态不是三态**:只有「当弹」拍位的品数字形变红,已弹
  与未弹**同色**(逐系统墨色直方图完全一致,无变灰/渐隐)。票面原设
  「已弹/当弹/未弹」三态中「已弹」一项被证伪,按视频实现两态。
- 高亮红 = **RGB(200,97,109)**(#C8616D),15 帧众数逐帧完全一致;
  与站方红线**同色**(线=字一个常量,本机 Flutter 线与页面 JS 染色
  共用 `faithfulHighlightRed`)。用户首测 (193,103,113) 为同源视频
  压缩抖动,以多帧众数为准。
- 变色范围 = **仅纯数字 text 且字号 ≥ 全页最大数字字号×0.9**(品数
  字 10.92px 入选);小节号 9.24px(比值 0.85)、和弦名(斜体
  Georgia)、PUA 字形(谱号/波音线)、谱线/符干/符梁 rects 全部排除
  ——与视频逐帧对照一致(符干符梁不随音符变红)。

**落地(与票面范围的对应):**

1. 染色:索引脚本**内联在横带页**(不经 JS 桥,OEM jam 面零):
   字体就绪后(`document.fonts.ready` + 2.5s 兜底)按「嵌套 svg 裁切
   片的盒包含元素中心」定属主片,strip x = 片 x + (中心 − 片左缘),
   按 Dart 算好的八分列网格(每小节 8 列)分桶。`UF.paint(n)` 绝对
   状态全量重刷 = 幂等,列变化率(~0.375s)经 JS 桥单发,丢发由下一
   列重发自愈;建索引前到达的指令进 pending。改色范围按视频两态。
   Python 镜像 + node 迷你 DOM 干跑双重验证(51 小节 542 个品数字
   恰好各入一桶,小节号/和弦名全排除)。
2. 逐帧平滑:16ms 轮询定时器 → **视图内置 ticker(vsync)**,拍位每
   帧按引擎时钟现算(ADR-0005 不破:时钟缝=控制器 visualNow 原样,
   页只在轮询里递会话锚)。原生 scrollTo 不变;同目标去重,暂停=
   时钟冻结零下发。轮询的逐帧抖动是上一版卡顿来源。
3. 曲头:左余量(视口宽/3)与曲尾右余量(视口宽×2/3)**烘进包装页
   padding**(Dart 注入数字,innerWidth 脚本删除)——scrollTo(0) 时
   曲头 0 恰在播放头线上,预备数拍期负拍钳 0 在线上等待;曲尾几何
   闭式:maxScroll = 横带宽,末拍触线而止。装载推迟到首个布局帧
   (余量要视口宽);视口宽变化(旋转/分屏)才付重装代价(装载代数
   门挡旧回调)。停止回闲时当弹列还原(paint(-1))。

### 2026-11-07 机检反二:scrollTo 限速实锤 → 跟滚改 rAF transform(已装机复检过)

装机机检第一轮抓到大病:**原生 scrollTo 在这台 OEM WebView 上不可用于
连续跟滚**。带 logcat 采样实证:ticker 以正确拍位/正确墙钟速率下发绝对
目标(~27Hz),显示却以 ~35% 速率爬行且滞后随时间增长(暂停对拍:提示
beat 62 vs 线 beat 20);同一时段 Flutter ticker 掉到 27Hz——该路径还
拖慢 Flutter UI 线程。第一版「ticker+原生 scrollTo」方案整体作废。

**改版(装机复检全过):**

- 跟滚 = **页内联 rAF 逐帧写 `translateX`**(合成器动画,亚像素):
  实测全速率(~150 device px/s ✓ vs 旧 36),rAF 不节流;Flutter ticker
  恢复正常。桥上只走列变化率(~2.7s 一次发)的 `UF.seek(beat,periodMs)`
  ——页内按拍周期死推,桥丢发由下一列重锚自愈;暂停=引擎时钟停走 8 帧
  检出 → `UF.hold()` 冻死推(实测 3s 零位移);恢复/回到开头=锚变更重置
  驱动立即重发 seek;停止=`UF.follow(0)` 复位(transform/overflow/
  scroll/染色,实测手动拖恢复)。
- 同步精度:暂停对拍 **提示第18小节·拍1 ↔ 线恰在印张第18小节小节线上**
  (旧 scrollTo 版差 25-30 拍);死推在列内线性插值,误差只剩桥延迟。
- **染色索引弃 rect 改属性**:第一版按 getBoundingClientRect 判属主片,
  机检抓到 OEM 盒测歪(filled=72/应 290)——改读属性(片 x/viewBox +
  数字 text 的 x 属性,两首 census 全带 x),装机日志 `slices=51
  assigned=542 filled=290` 与 PC Python 镜像逐数吻合。
- 染色上屏实证:当弹列字形红 RGB(200,97,109)(与线同色逐像素一致),
  其余全黑;小节号/和弦名/谱线不变色 ✓ 两态模型与视频一致。
- 曲头 0 落线(预备期负拍钳 0)✓;停止回闲复位 ✓;logcat 干净 ✓;
  flutter 1017 全绿。

诊断缝追记:页内 `console.log` 经 `setOnConsoleMessage` 回传 Dart 是
WebView 内部状态的最好观测口,两次定位(限速实锤、filled=72)都靠它。

### 2026-11-07 机检反三:用户报「声音与时间线不同步 + 开始卡顿」→ 桥批冲刷延迟实锤,三方修复(已装机复检过)

console 回传实测(`Date.now()-te`,epoch 同源):逐列 seek 的到达延迟
**57-484ms 且相邻两发抖动 ±150ms+**,并见 3ms 间隔成对到达——OEM 桥
按批冲刷,逐列重锚把排队延迟逐列注入时间轴 = 「不同步」根因。「开始
卡顿」根因另案:prep 期首条负拍 seek 后页内死推照跑,预备 3s 内容前
爬 4 拍、音乐首拍 seek 又拽回 0(前爬+回跳)。

**修复(装机复检全过):**

1. **prep 冻结**:负拍 seek 在页内钳 0 + 当场 `hold()` 冻死推、
   transform 置 0(实测 prep 暂停期 3s 零位移)。
2. **染色改页内时间轴驱动**:rAF 每帧按死推拍位现算列号、变列才
   `color(col)`——桥上**不再有逐列指令**,染色与滚动同一时间轴,
   天然互锁。
3. **seek 低调频**:仅首发锚/跨 0(预备→正曲、回开头)/每 4 拍周期
   校正(`stripNeedsSeek` 纯函数,测试覆盖)。批压力降一个量级。
4. **时延补偿**:seek 携带发送时刻 epoch ms,页取观测最小延迟前推锚
   (`a=b+lat/per`);残余抖动由 150ms 软校正滑入(≤25px),大偏差
   (回开头)仍硬切。

锚定;播放 20s 暂停对拍 **提示第15小节·拍1 ↔ 线恰在印张第15小节线**
;prep 冻结 0 位移;染色照常;净版重装再跑一遍全链同结论;logcat 干净;
flutter 1017 全绿。装载竞态窗口(冷启即开弹)内容落后至装载完成+首个
周期校正(≤4 拍),遮罩在,自愈有界——不另设启动重试。
