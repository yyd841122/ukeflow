# 04: 收件目录+检测按钮+谱型判别+Dart 解析器移植(通用化阶段)

**Status:** ready-for-agent

**Blocked by:** 01, 02, 03

**What to build:** 把票01/03 的 PC 端解码能力移植进 App,落地「其他内容」阶段的
通用入库流。范围:

1. **收件目录**:SAF 文件夹授权一次,App 持久化授权;授权/换目录入口在曲库;
2. **检测按钮**:曲库界面手动触发扫描收件目录;按文件指纹(内容哈希)记账,
   不重不漏;扫描/转换过程可见,失败逐文件报错不中断整批;
3. **Dart 解析器**:移植 Python 解码器(票01 规则集+票03 弹唱侧),黄金断言
   同步移植(两首样本文件作为 fixture,skip-if-missing 纪律);解析输出同构于
   PC 端产物(同一份识谱源/ChordPro),确保「PC 验证过的谱 App 再解析结果不变」;
4. **谱型判别**:指弹谱(有四线 TAB)→ 识谱源入库(ADR-0009 导入面);
   弹唱谱 → 票03 已支持则走弹唱入库,未支持变体检出并标记「待支持」,不静默丢弃;
5. **体检闸端内复刻**:PC 闸规则在 App 端同型实现(全绿自动入库/红旗列疑点
   待确认);原始 HTML 存档入库(存源模式,ADR-0009 同型),坏源 Broken 兜底;
6. **下载器接口契约落文档**:一个 HTML=一首曲=一个完整渲染块;元数据从谱面
   内容读(文件名无关);外部独立项目按此产出投放收件目录。

**验收:**

1. 把两首样本放进收件目录,App 内点「检测」→ 两首自动入库(票01/03 已入库的
   按指纹跳过),全程不接电脑;
2. 构造坏文件(截断/非渲染块/拍数不闭合)→ Broken/红旗呈现,不崩、不静默;
3. 真机全流程演示:放文件→检测→入库→跟练,用户上手验收。

**Non-goals:** 联网采集/WebView 拉页(grill Q7 拆出,归外部下载器项目);后台
定时扫描(Q13 明确不做,留以后另议);批量重命名/文件管理功能。
