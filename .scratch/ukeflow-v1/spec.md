# UkeFlow v1 产品规格：从 0 到 1 掌握弹唱

Status: ready-for-agent

依据：GLOSSARY.md（术语）、docs/adr/0001~0006（已定决策）、docs/architecture.md（架构与里程碑）、docs/research/similar-projects.md（调研）、spikes/tech_validation/README.md（三项技术押注已真机验证）。

## Problem Statement

我是尤克里里新手：会按几个简单和弦，但从没完整弹会过一首歌。现在的练习方式处处断链——

- 网上谱子绝大多数是图片谱，纸一样钉在屏幕上：不能跟、不能播、不能提示我"现在弹哪下"；
- 调音要另开 app，节拍器要另下一个，练某首歌时和弦按法要翻网页，工具之间互不认识；
- 没人告诉我每天该练什么、练到什么程度算会了，全靠自己东一下西一下，坚持不下去；
- 弹得对不对全凭感觉，连"这首歌听起来应该是什么样"都没个可靠的参考。

我需要一个把「调音 → 认识和弦 → 练稳右手 → 跟练成曲 → 打卡坚持」串成一条路的东西，让我从 0 真正掌握自己点名的目标曲的弹唱。

## Solution

UkeFlow：一款纯自用的尤克里里弹唱学习 App（Android 先行）。

- **工具齐**：内置调音器（麦克风检测音高，±5 音分判准）、和弦库（指法图+按法要点+试听）、节奏型训练器（节拍器+↓↑ 箭头慢练）。
- **谱是活的**：曲谱以文本谱（ChordPro）为一等公民，进入跟练前预编译成**动作事件时间轴**。跟练时歌词随节拍滚动、当前拍扫弦箭头高亮、侧边"俄罗斯方块"式预告接下来几个动作——时间同步以音频引擎时钟为**唯一时钟**，音画同步是结构保证，不是校准出来的。
- **弹前能听**：示范试听按所选节奏型扫弦、指弹谱逐音播放，音源采样优先、Karplus-Strong 合成兜底，"一耳朵是尤克里里"。
- **有路可走**：内置练习路径（从认识和弦到完整弹唱），由每日任务+打卡组成；内置曲库覆盖 5 首目标曲，开箱即练。
- **谱进得来**：粘贴"和弦+歌词"文本一键解析、粘贴 Cifra Club 链接自动抓取；所有导入必过自建校验才能入库。图片谱 v1 提供只读查看器。

## User Stories

### 调音器

1. 作为学习者，我想打开调音器就看到 GCEA 四根弦的目标音，以便知道每根弦该调到哪。
2. 作为学习者，我想拨响一根弦后立即看到检测到的音名和偏差音分，以便判断该拧紧还是放松。
3. 作为学习者，我想在偏差进入 ±5 音分时看到明确的"已调准"提示，以便放心开始练习。
4. 作为学习者，我想在安静或不弹琴时调音器不乱报音高，以便不被噪声误导。
5. 作为学习者，我想读数带适度阻尼不疯狂跳动，以便专注调弦不被干扰。

### 和弦库

6. 作为新手，我想浏览常用和弦的指法图（品位点、手指编号、空弦与闷音标记），以便照着按。
7. 作为新手，我想看到每个和弦的按法要点与常见错误提示，以便少走弯路。
8. 作为新手，我想点一下和弦就听到它的示范音，以便核对自己按出来的声音对不对。
9. 作为学习者，我想按字母/难度分组浏览和弦，以便快速定位。
10. 作为学习者，我想搜索和弦名直达详情，以便练琴中途快速查阅。

### 节拍器与节奏型训练

11. 作为学习者，我想设定 BPM 并启动/停止节拍器，以便稳定右手。
12. 作为学习者，我想听到 4/4 拍强弱分明的节拍声，以便数拍不乱。
13. 作为学习者，我想选择节奏型（如"下 下上 上下上"）并看到 ↓↑ 箭头随节拍逐个高亮，以便慢练扫弦。
14. 作为学习者，我想把节奏型放慢到任意 BPM 逐拍练，以便形成肌肉记忆。

### 跟练：弹唱谱

15. 作为弹唱练习者，我想打开弹唱谱进入跟练，看到歌词随节拍滚动、当前行高亮，以便边弹边唱不丢词。
16. 作为弹唱练习者，我想在谱面和弦位置看到和弦指法小图，以便转换和弦时不用翻书。
17. 作为弹唱练习者，我想看到当前拍的扫弦方向箭头并高亮，以便右手知道此刻扫哪里。
18. 作为弹唱练习者，我想在侧边看到"俄罗斯方块"式的接下来若干动作预告，以便提前准备和弦转换。
19. 作为弹唱练习者，我想当前动作突出显示、过去动作淡出，以便一眼看清练到哪了。
20. 作为弹唱练习者，我想任意调节跟练速度（如 50%–100% 原速），以便从慢速逐步提速。
21. 作为弹唱练习者，我想开始前有几拍预备数拍，以便做好准备再进歌。
22. 作为弹唱练习者，我想暂停、继续、回到开头，以便卡住时从容重来。
23. 作为弹唱练习者，我想为同一首谱更换节奏型，以便用不同扫法练同一首歌。
24. 作为弹唱练习者，我想开关跟练中的参考音（节拍声/示范扫弦声），以便先跟拍、后脱拍。

### 跟练：指弹谱

25. 作为指弹练习者，我想打开指弹谱看到四线谱，逐音显示哪根弦哪个品位何时弹响，以便逐音跟练。
26. 作为指弹练习者，我想当前音与即将到来的音有不同的视觉强调，以便左手提前移动。
27. 作为指弹练习者，我想指弹谱跟练同样支持调速度与预备数拍，以便获得与弹唱谱一致的练习体验。

### 示范试听

28. 作为学习者，我想在弹唱前点"示范试听"，听到按所选节奏型扫弦的真实感音效，以便对整曲听感有预期。
29. 作为指弹练习者，我想听到指弹谱逐音示范播放，以便知道这首曲子本来听起来什么样。
30. 作为学习者，我想示范音做到"一耳朵是尤克里里"（免费采样优先、物理建模合成兜底），以便参考音可信。

### 练习路径与打卡

31. 作为新手，我想有一条内置练习路径：从认识和弦、右手稳定，一路到完整弹唱一首目标曲，以便不用自己安排学什么。
32. 作为新手，我想每天打开 App 就看到今天的每日任务（学什么+练什么），以便直接开练。
33. 作为新手，我想完成任务后打卡，以便记录进度并获得成就感。
34. 作为学习者，我想看到路径总进度与连续打卡天数，以便保持动力。
35. 作为学习者，我想每日任务一键直达对应的和弦页/节奏型训练/跟练页，以便少点几层导航。
36. 作为学习者，我想任务可以补卡（标记补练日期），以便生活打断后续上而不焦虑。
37. 作为学习者，我想路径推进按"完成顺序"而非死板的日历日，以便按自己的节奏走。

### 曲库与导入

38. 作为学习者，我想在内置曲库按歌名浏览并直接进入跟练，以便离线开箱即用。
39. 作为学习者，我想内置曲库覆盖我的 5 首目标曲（爱你不是两三天、沧海一声笑、Big Big World、Love You More Than I Can Say、Yesterday Once More），以便从第一天就能练自己想弹的歌。
40. 作为曲库维护者，我想以文本谱格式手工录入新歌进曲库，以便任何想练的歌都能进来。
41. 作为学习者，我想粘贴"和弦+歌词"纯文本一键解析成文本谱，以便把网上找到的谱快速搬进来。
42. 作为学习者，我想粘贴 Cifra Club 页面链接自动抓取并解析成文本谱，以便少手工搬运。
43. 作为学习者，我想在内置搜索页（Cifra Club）搜歌名找到曲谱页面，以便形成"搜索→导入→跟练"的闭环。
44. 作为曲库维护者，我想让导入的谱必须通过校验（段落闭合、和弦名合法）才能入库，以便坏谱进不了曲库。
45. 作为学习者，我想查看图片谱（缩放、平移），以便对照网上主流的中文图片谱——只读，不能跟练。

### 数据与设置

46. 作为学习者，我想把全部数据（自建曲谱/打卡/设置）导出为备份文件并能再导入，以便换机或误删不丢数据。
47. 作为学习者，我想在设置页调整 A4 参考音高、默认 BPM 等，以便个性化工具行为。
48. 作为学习者，我想 App 完全离线可用（链接导入与搜索除外），以便随时练琴不依赖网络。

## Implementation Decisions

### 平台与骨架

- Flutter 3.44 / Dart 3.12，Android 先行，架构保持 iOS 可迁移（ADR-0001）。状态管理 Riverpod，存储 drift（SQLite）。
- 模块分三层：**核心层**（音频引擎封装、曲谱数据模型、时间轴编译与校验）、**数据层**（drift 表 + 内置 assets：曲谱/和弦数据/采样）、**功能层**（调音器、和弦库、节奏型训练、跟练、示范试听、练习路径、曲库与导入）。模块职责见 docs/architecture.md。
- spikes/tech_validation 不进正式工程；调音器逻辑升级迁入，spike 工程保留作参考，M2 结束后归档删除。

### 同步引擎（产品核心，ADR-0005）

- **唯一时钟** = 音频引擎的 getEngineTime()。产品内一切音画对齐只认它，禁止挂钟参与。引擎时钟与挂钟存在 ~73ppm 固有晶振速率差（spike B 实测 22.1ms/5min），无需也不应校准。
- 曲谱进入跟练前**预编译为动作事件时间轴**：每个事件含（引擎时刻、类型、数据），类型覆盖扫弦（方向+和弦）、单音（弦+品位）、歌词行、段落标记。
- 跟练视图是**纯函数**：（引擎时刻）→ 练习状态（当前拍、当前动作、预告窗口、高亮歌词行）。UI 以 ~16ms 轮询重绘（spike B 已验证此模式漂移可忽略）。当前动作按二分查找定位；"俄罗斯方块"预告=取（now, now+lookahead] 时间窗查询。
- 一切发声——节拍 tick、扫弦采样错峰、合成拨弦、逐音示范——都经 playClocked 采样级预定，且与视觉事件出自**同一份时间轴**。音画同步是结构保证，不是校准出来的。

### 曲谱模型（ADR-0002/0003/0006）

- 文本谱（ChordPro）是唯一一等公民曲谱格式；图片谱 v1 只提供只读查看器（photo_view），明确不能跟练。
- 弹唱谱与指弹谱是**两个独立的一等公民模型**，不强行统一：弹唱谱=和弦+歌词+节奏型标注；指弹谱=逐音事件（弦/品位/时刻）。v1 指弹谱仅限内置手工录入。
- 解析采用 chord_pro 0.8.0。spike C 已实证三个语义，实现必须遵守：Chord.root 只含根音字母（quality 分离存储）；{transpose: n} 指令不改动 token 流、移调必须显式调用；解析器极宽容（未知指令静默、段落未闭合静默自动闭合、几乎不产生 error 诊断）。
- 因此**谱面校验是 UkeFlow 自己的责任**：段落闭合检查 + 和弦名白名单（对照和弦库数据）。所有导入路径（文本导入/链接导入/手工录入）必须过校验才能入库。
- 中文歌词与 [和弦] 记号紧贴（无空格）可正确解析、歌词逐字保留（spike C 已验证）。

### 音频（ADR-0004/0005）

- flutter_soloud 单库覆盖四类发声（节拍器、扫弦触发、拨弦合成、逐音示范）；内存 PCM 经 loadMem 注入。
- 节拍 tick 用代码合成 WAV，无资源文件（spike B 模式）；调度采用 400ms 提前量窗口 + 40ms 轮询（spike B 已验证参数）。
- 音源策略：免费许可（CC0 等）采样优先，缺口用 Karplus-Strong 拨弦合成兜底；音源与调度引擎解耦，日后升级采样库不动引擎。
- 调音链路：record 采集 PCM16/44.1kHz/单声道 → pitch_detector_dart（YIN，2048 窗口）→ 音名/音分换算。目标 GCEA = G4/C4/E4/A4，±5 音分判"已调准"（spike A 真琴已验证）。

### 数据

- drift 表：打卡、自建曲谱、设置。内置 assets：5 首目标曲文本谱、和弦指法数据（chords-db ukulele.json，MIT）、采样音源。
- 备份=本地文件导出/导入，无云、无账号。

### 导入（ADR-0002/0006）

- 文本导入：宽容解析 + 自建校验把关，"宽进严出"。
- Cifra Club：WebView 加载页面后从 DOM 提取内嵌和弦数据（站点有 Akamai 反爬，**禁止**服务端 HTTP 直连爬取）。v1 仅此一个搜索源。

### 节奏与速度约定

- v1 节奏型按 4/4 拍设计；内置若干基础节奏型（下、下上、上下上等组合）。
- BPM 在进入跟练前设定；时间轴按该 BPM 编译，跟练中不变速（v1 简化）。

### 实施顺序

- M1 地基（正式工程+骨架+和弦库）→ M2 音频核心（节拍器/节奏型训练/合成拨弦/和弦示范音）→ **M3 跟练引擎（核心，预算可上浮）** → M4 路径与曲库 → M5 打磨收尾。每里程碑结束：真机可用、可演示。

## Testing Decisions

- **好测试只测外部行为**：给定谱文本+时刻，断言练习状态；给定 PCM 帧，断言调音读数；给定粘贴文本/网页 DOM，断言校验放行或拦截；给定 DAO 操作，断言打卡与进度数据。不测私有实现细节，不测渲染样式。
- **四条测试接缝**（已与用户确认）：
  1. **练习内核（核心缝，纯函数）**：谱文本+设定 → 动作事件时间轴；（时间轴，引擎时刻）→ 练习状态。不依赖音频/UI/数据库，标准 flutter test 覆盖。音画同步的全部正确性锁死在这条缝上。
  2. **导入管线（窄缝）**：粘贴文本 / Cifra Club DOM → 校验后的谱。fixture 驱动，复用内核的校验层。
  3. **调音管线（准纯缝）**：PCM 帧 → 调音状态。fixture 录音驱动。
  4. **持久化（标准缝）**：drift 内存库测 DAO。
- **刻意不设接缝**：音频引擎（flutter_soloud，ADR-0005 已真机验证的外部依赖——内核侧定义薄接口，测试用假实现，真机听感走演示验收）；UI 渲染（练习内核状态的薄渲染，真机演示验收）。
- **先例**：spike C 的解析自动化测试（4/4 通过）即接缝 2 的雏形，可迁入正式工程继续有效；drift 用官方 in-memory 测试模式。
- **目标曲冒烟**：5 首内置目标曲的谱各配一条编译测试——能解析、能编译成时间轴、出现的和弦名全部在白名单内。
- **真机演示门**：听感、手感、"跟练跟不跟得上"只能真机判断——每里程碑末的真机演示就是它们的验收测试。

## Out of Scope

- iOS 构建与适配（架构保持可迁移，v1 只在 Android 真机验证）。
- 实时评判（听麦克风判断弹对弹错）——推迟到 v2 评估，不阻塞 v1。
- 图片谱→文本谱转换工具、图片谱跟练（ADR-0002 明确推迟 v2）。
- 指弹谱在线搜索/导入（ADR-0003 明确排除）。
- 移调 UI（chord_pro 的显式移调能力就位，但 v1 不暴露界面入口）。
- 录音棚级采样库、力度层次。
- 云同步、多用户、账号体系。
- Cifra Club 之外的更多搜索源；通用"任意谱站导入"。
- 跟练中实时变速；4/4 以外的拍号。
- 正式发布工程化（签名、应用商店、崩溃上报）——纯自用 sideload。

## Further Notes

- **产品哲学（用户明确约束）**：最终目标是真正好用的产品，质量优先于工期；总预算 6~10 周可按实际延长。M3 跟练引擎是"好产品"的主战场，宁可慢、不可糙。
- **内容工作是硬任务**：5 首目标曲需人工录入为文本谱并核对节奏型与和弦指法，安排在 M3 内完成，不要拖到最后。
- spike 留下的工程教训：Dart 3.12 移除了 Duration.difference()（只能用 - 运算符）；pub 缓存在国内镜像路径（pub.flutter-io.cn）。
- 真机为 OPPO PCAM00，WSL2 经无线调试 adb connect 连接（方法见 spikes/tech_validation/README.md）。
- UI 语言中文；写码、命名、工单一律使用 GLOSSARY.md 的词汇（弹唱/跟练/节奏型/和弦指法/每日任务/打卡等），避免术语漂移。
