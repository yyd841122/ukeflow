# 41: PDF 记号普查工具——转录辅助(路径A),gs-aini 真值验证

**What to build:** repo 内开发侧 Python 工具 `tools/pdf_census.py`(不进 app、零 Flutter 依赖):对谱全了式位图 PDF 做**记号普查**——按系统输出「记号事件表」(拍位 × 记号类 × 弦线 × 置信标记),人工照表对 PDF 校验后落 `ScoreSheetDef`。定位是**转录辅助**不是 OMR 引擎:承诺「枚举全 + 不确定显式标出」,不承诺「识别对」;最终准确度由既有互证测试 + 人工校验/听验保底。

**背景与依据:** 2026-10-25 工单39 像素考古已证:曲源 PDF 全为嵌入位图(无矢量/文本层,OMR 引擎的矢量路径为空集);弦距 14px(render scale3)= app `tabLineGap` 14,像素几何 1:1 直移;×/波浪/箭头/两种休止/长音椭圆/震音椭圆的形状与尺寸均已实测建档。普查脚本原型当轮已跑通 70%(系统/小节线/连通域分类)。

**形状档案(实测,内置于分类器):** × =两笔交叉 10×14 笔画2.2;堆2/3/4 =高26/40/54 宽≤14;波浪 =同尺寸但行剖面单笔(蛇形),与堆4靠中档行 run 数判别;箭头 =同尺寸+端部行宽 ≥8(上/下看宽行在顶/底三分段);八分休止 =实心点10×6.5+尾(顶部40%行填充率≥0.6、总高≤20);多拍休止占位 =宽≥28 高≤18 坐①线;长音椭圆 =14≤w≤28、16≤h≤30 空心;震音椭圆 =h≥44 空心;品位数字 =8×12 均匀致密。

**拍位标定(最弱列,半自动):** 自动拟合不稳定(印张 px/beat 逐系统不等宽、小节线与拍格存在 ~0.3 拍系统偏移)。v1 策略:验证态用真值锚(和弦行)逐系统最小二乘拟合;生产态由人工每系统给 1-2 个锚。标定残差随表输出。

**覆盖兜底:** 按 0.5 拍格核对每槽检出数,零检出且无休止/延音解释的槽标「空白待查」——防「印张拍 108 后还有十段未转录」这类整段遗漏(工单39 实际踩过)。

**验证(本票收口条件):** 对 gs-aini 跑普查,与既有真值(工单37-39 人工数据)diff,按记号类输出查准/查全;真值经 `tools/dump_score_sheet_json.dart`(组合定义→JSON)导出,工具本身不解析 Dart。**数字达标**(见验收)方可用于下一份谱(gs-bbw);不达标则降级为「定位辅助」并在票面记结论。
