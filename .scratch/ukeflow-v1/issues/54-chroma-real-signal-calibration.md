# 54: Chroma 真机「错」判定系统性偏 C——插桩定案与调参

**Status:** done

**现象:** 两次真机评分会话,「错」判定与和弦类型强相关,同手同琴同场:
- 10-30 送别(78bpm):踩上 16 格,错 13;C 密集段几乎全灭
- 10-31 两只老虎(50% 变速):踩上 18 格,**C 槽 9/12 错,G 槽 2/4 错,G7 槽 3/3 过**——镜像不对称

**已排除(证据固定):**
1. **阈值/算法/数据无罪**:合成探针矩阵(理想信号,含泛音 8 列/失谐 ±25¢/±40¢/闷一弦)全部 0.85+ 过 0.6 闸,C 0.85–0.98 与 G 0.81–0.93 对称;和弦库 C 主指法 [0,0,0,3] midi [67,60,64,72] 核实无误。「阈值偏严」不成立,单纯调 0.6 无效。
2. **琴调音/手型无罪**:调音器逐弦实测(10-31,C 手型):G4 391.1Hz(-4¢)、C4 259.9Hz、C5 526.4Hz(+12¢),在准。

**待判假设(按优先):**
1. **真实信号链未建模因素**(麦 HAL 厂商处理/慢扫弦弦间铺开/房间反射)——插桩可判
2. **C 槽位窗口实际内容非 C**(用户跟丢拍点时手位滞留旧和弦/移动中,窗内混音)——插桩可判
3. **评分嘀声泄漏进色度窗**:`_onPcmChunk` 实锤存滤前 PCM(controller L508),嘀声 880/1320Hz=A/E 类会进 [onset−20ms,+300ms] 窗(用户整体偏早 91ms 时必中);但方向性推演:嘀声正交污染应伤 G/G7 重于 C,与实测相反——**待排除,非主嫌**

**下一步:** `[DEBUG-chroma]` 插桩(debug 包,`practice_scoring_controller.dart` 的 `_verifyChord`/`_chromaBest` 路径):逐格 dump 槽位/和弦/窗长/窗内色度 top 音高类/bestMatch/score → 一次真机弹奏(两只老虎 50%,同protocol)回灌 logcat 定案。修复方向视数据定(窗策略/归一/模板构造/阈值皆有候选,不许先射箭)。

**测试缝:** 修复合入时把探针模式转正为回归(chordSignal 合成 builder 在 `test/core/scoring/chroma_test.dart` 现有基础上扩泛音/失谐/闷弦变体 + 断言分数余量);真机回灌数据做黄金样张。

**Blocked by:** 无(插桩本身零依赖;需用户配合一次弹奏)
