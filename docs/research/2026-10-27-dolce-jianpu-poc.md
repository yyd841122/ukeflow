# dolce(悦谱)简谱识别 PoC——谱全了样张实测(工单47 第一步子任务)

**结论:对工单 49,dolce 不能当识别引擎,可当高价值互证对照源。**
样张(gs-aini p0)上,人声段简谱读出质量实测极高(度数/时值/八度点/连线/休止
与人工台账逐项吻合),但其输出无坐标无证据链、无拍位,按 49 的契约(证据齐全、
对齐拍位骨架)不可直接采信;且裁条喂入时首系统会整体塌成休止符,稳定依
赖整页上下文。

## 实测设置

- dolce 0.8.5(MIT,github.com/lodebar2026/dolce),`scripts/omr-cli.mjs`
  纯 node 离线推理(onnxruntime-node,PP-OCRv4 det + v6_small rec,模型随仓)
- 装机注意:onnxruntime-node 安装脚本拉元数据清单不跟 302 会挂,
  `ONNXRUNTIME_NODE_INSTALL=skip npm install` 跳过(二进制本随 tar 自带)
- 输入(本工作台 band 检测产出):gs-aini p0 整页 PNG(1786×2526,scale3)
  + 三个系统的简谱区裁条(y441-625/793-958/1099-1268)
- 输出格式 `-f 123`(ABC 方言);单页整页 ~6.7s,裁条 ~1s,全离线

## 实测结果

**元数据/歌词(整页):全对。** 标题「爱你不是两三天」、演唱「梁静茹」、
调号 `K:1=E`、拍号 4/4、速度 `Q:1/4=78` 与权威台账(1=E 78bpm)一致;
编谱者读「小埋」实为「小理」(单字 OCR 误)。歌词条按音符位置切分并带
韵脚斜杠结构。

**人声段简谱(sys1/sys2 裁条):质量极高。** 首句「你的信只留下最后一封
淡淡笔迹」读出:

```
|: 5'_. (5'__ 5'_) 1''_ 6'_. (6'__ 6'_) 1''_ | 5'_ 5'_ 6'_ (3'_ 3') 0_ 3'__ 2'__ | …
w:你的/信只留/下最后一封/淡淡笔迹/你熟悉的/温柔//请别
```

对照 app 人工真值(builtin_tab_charts,b6「的/留 各为 附点八+16 同音连线,
b7 八分休止后淡淡 16 分对」):**度数(5 5 5 1…)、附点、双下划线、同音连线
括号、休止、16 分对全部吻合**;八度点读出 5'/1'' 恰为印张原样,与 app
「八度约定=印张点数减一」约定严丝合缝。反复记号 `|:`、小节线、乐句结构
行均正确。

**失败模式(三条,都实测到):**

1. **裁条上下文敏感**:sys0 裁条(前奏段)整条塌成 `0 0 0 0 |…`(22 休止),
   同一行在整页输入下却能读出 `2_ 6- 7_ 1_ | X_- 2_- | 3-`(部分);放大 2x/3x
   无效。其行判定依赖整页版面上下文,喂条带时首行易判死。
2. **TAB 行成垃圾行**:整页输入下四线谱行被当乐谱行硬读,出一串
   `X X | X X |`、`((X- ((1-)) X_))` 噪声行夹在正常行间——谱全了四层版式
   (和弦图+和弦名/TAB/简谱/歌词)超出其「全页简谱诗歌本」的版面假设。
3. **八度点不稳**:同一小节整页与裁条两次读出 `1_` vs `1''_`,八度点
   检出随输入抖动;调号同样(整页 E、裁条 C)。

**X = 静默未知**:读不出的数字落 `X` 混在拍里,无置信度无坐标——与
UkeFlow「不支持记号显式报错、证据链强制」纪律正面冲突。

## 对工单 49 的判定

- **「借其输出对齐拍位骨架」不可直接成立**:123 文本无像素坐标、无逐音
  bbox/置信度,对齐只能按音序做序列比对(且 X 段断裂破坏对齐)——而自研
  PaddleOCR+几何路线天然带坐标可直接落拍位。证据链契约(page/bbox/裁图/
  置信度)它一项都不满足。
- **作互证对照源:可用且成本低。** 裁条喂入下人声段度数/时值/八度读出
  与人工台账全对,把 dolce 输出当「第二意见」与自研草稿逐音 diff,分歧位
  即人工校对热点——正好喂工单 51 校对台的对照模式。
- **若 49 自研路线撞墙,回退路径存在**:整页输入+后处理滤 X 垃圾行,人工
  补齐后仍能出带结构的旋律草稿,但其无坐标本性决定了只能走「音序对齐+
  人工逐位确认」的更重流程。

PoC 级限制:仅 gs-aini p0 一页、单曲;副歌高置段(印张双点)未专项验证。
