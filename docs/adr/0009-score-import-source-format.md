# PDF 识谱导入:ScoreIR 是源格式,不造第三种谱格式

2026-10-26 定向(三轮方案拷问+两轮公开调研,落地为工单 42-52):把网上下载的曲谱 PDF 变成 App 内可跟练的谱面。识别端走**离线 Python 工作台半自动管线**(谱面体检/谱型判别 → 版面切分 → 简谱/TAB 识别 → 本机 web 校对台人工逐位确认 → 导出 ScoreIR JSON);消费端 App 以 **ScoreIR 源 JSON 为唯一真源**——与自建弹唱谱存 ChordPro 源文本同型:加载时物化为既有组合结构(ScoreSheetDef + TabChart×2,喂 buildScorePlaybackChart),校验失败显示已损坏;App 内轻改 = 改源再物化。运行时谱面模型仍是 ADR-0003 双模型 + ADR-0008 组合视图,**不引入第三种运行时谱格式**(统一谱格式第三次被排除)。谱型判别(自动猜+可手改)只分流:独奏谱 TAB → 完整管线;弹唱谱/认不出 → 归档图片谱待识别。第一期输入主型 = 谱全了式独奏谱 PDF(TAB 已印在纸上,无需编配);金标准 = aiNiBuShiLiangSanTian 人工录入数据逐位对照。

## Considered Options

- **ScoreIR 作应用内单一事实来源**(ChatGPT 方案三路线):推翻 ADR-0003/0008 分界,曲库数据层与跟练/混播接驳全部重写。否。
- **确认时单向物化,App 只存物化结果、IR 归档**:两套表示、轻改需回写;CustomCharts「存源+加载物化+Broken 兜底」先例证明存源更简。定存源模式(本次拷问中对早前约定的修正)。
- **引入 alphaTab 做渲染/播放**:无 Flutter 集成(JS/.NET/Android 原生);自有谱面渲染器 + SoLoud 双轨引擎已真机验收(工单 38/39)。否。
- **一期新做流水谱界面**:谱面视图已带固定播放头(视口 1/3)流水跟滚 + 四层跟随高亮,直接充当流水跟弹;大音符判定线版列为观察项。否。
- **走 MusicXML 中枢**:出版社记号语义丢失、双道格式转换;MusicXML 降级为可选对外交换。否。

## Consequences

- drift 新表存导入谱源 JSON(含 schemaVersion),曲库独奏谱类目合并 builtin + imported,坏源 Broken 兜底(同 CustomCharts 模式)。
- **物化器是纯函数,必须先过金标准往返等值测试**(builtin 常量 → IR → 物化 → 逐位相等)才准接播放——这是防语义损耗的总闸。
- 时值/符杠/附点/tie 仍由拍位推导(模型不变);识别端职责 = 把纸上节奏符号算成**拍位**,经校对台人工确认才算数。识别产出永远带证据(page/bbox/裁图/置信度),禁止静默丢符号,不支持记号显式报错。
- 谱型判别误判可手改;弹唱谱识别分支、端内识别、打卡联动、大音符流水谱均后置为观察项;工单 37 预留的 0009 号由本 ADR 占用,GP 文件导入不立项(与 MusicXML 同列可选对外交换)。
- 识别端选型有两轮调研背书(docs/research/2026-10-25-omr-tab-survey.md、2026-10-26-vlm-jianpu-tab-scan.md):开源无四弦 TAB 轮子;简谱层先试 dolce(MIT),TAB 层规则化自建(数字 OCR+模板匹配);Soundslice 免费档 PoC 一次(已知 tab-only 全四分音符缺陷,不作依赖)。
