# 独奏谱读取端方向:评测底座先行,VLM 直读 TAB 主线

2026-11-02 定向(grill 会话 + Codex 独立评审 review-plan,threadId `01a19a36-81e0-7330-874a-d47b122e517c`,裁定原草案 MAJOR GAPS 后采其修订;用户逐条确认):工单 39 验收暴露根因——谱面数据 vs 权威印张的偏差源自**读取端**而非渲染:机读管线 TAB 数字配对仅 3-8 对、配对内正确率 0-17%、技巧 F1 0.24;人工像素考古同样出错(字形误读、堆vs单音×4、符杠系统先读反后纠正);逐字形人工修正不可扩展。用户裁决:**读文件时就读准**,方向从「修数据」转为「提升读取端」。分层事实:简谱旋律层近解(dolce POC 2026-10-27 实测人声段度数/时值/八度点/连线/休止与人工台账逐项吻合,但无坐标/无拍位/裁条喂入塌);**TAB 层(4 弦弦品+杆底符杠节奏)是核心缺口**,无已验证开源方案(PhotoScore/SmartScore 有官方声称未验,Soundslice tab-only 节奏不识别且免费档无导出);和弦层已解(37 手读)。

## Decision

1. **评测底座先行,后考试**:先建「冻结的已裁定评测集」+「联合事件 F1 评分器」(工单 56),任何候选读谱方案的分数在可比的尺子上产生。联合事件 = 弦品+起音拍位+节奏三件套全对才算一个对;计数单位/对齐规则/容差在评分器内固定;节奏比较用有理数精确匹配(容差 <1/32 拍且小于最短相邻起音间隔之半);旧 ±0.35 拍容差只作空间漂移诊断不作节奏标准。**历史转录(484 音)只作参照不作评测真值**(含错且与播放事件语义层级不匹配——约半数发声音来自 ×+指形展开)。
2. **语义分层评估**:印张符号读取(×/数字/符杠)与「统一规则展开→播放事件」分开计分,展开规则单源、对所有候选一致;不给任何一路单独喂人工推导。
3. **候选路线**:主线 = **VLM 直读**(工单 57:整页 vs 系统裁块对照,模型 `deepseek-v4-flash-vision-exp`,用户自备 DeepSeek key,**首轮 API 支出硬上限 ¥20**,烧完 = 证据不足而非技术失败);dolce 适配验证(整页上下文/抑制非简谱区/输出回映射);Soundslice 降级为免费档界面能力检查(52,导出付费不依赖);PhotoScore/SmartScore 限时筛选 + 换源限时检查(工单 58);壹谱网留后手。**自研像素管线强化弃投**。
4. **晋级与验收**:探索参考线旋律 0.95/TAB 0.90;晋级线 = TAB 联合事件 F1 ≥ 0.90(整页/裁块至少一种形态达到);产品总闸 = ≥3 首未见整曲、单首人工校对 ≤30 分钟(计入选页/修切分/录和弦/查错/纠错/导出/App 验证,主动工时单列、逐首报告不报均值)、校对后 **0 个未解释的音位/节奏/休止差异**(结构校验通过不替代内容复核)。
5. **退路链**(全灭按序):结构化换源 → 商业 TAB 引擎 → 有工时上限的混合读取+校对 → 限缩支持谱型/暂停位图自动导入。
6. **与 ADR-0009 的关系**:实验阶段(PoC/工作台内)输出不受其「离线/证据链/逐位人工确认」契约约束;**接入产品的输出须显式修订 ADR-0009**(哪些约束保留哪些放开,届时单独决策),不默默绕过。

## Consequences

- 工单 56(评测底座)/57(VLM POC)/58(候选筛选)立;52 范围收窄(免费档只查界面能力);39 保持挂起,484 音降级为历史转录参照,其争议项(8vs5/4vs7/堆vs单音/「0」列)纳入 56 的裁决流程。
- Codex 评审全文存档于评审任务记录,五维 findings 与逐条裁定已消化进本 ADR 与工单;评审保留项(真值分「已裁定/待裁定/未覆盖」三类、待裁定项公布数量与覆盖率)落进 56 的验收。

## 追记(2026-11-03,工单58 收口后):退路链前两环实证落空,升第三环

- **第一环(结构化换源)落空**:四曲(gs-aini/BBW/MTICS/YOM)平台矩阵全线未命中——谱全了编配为站方私有(.ibe 加密,官方产出仅渲染 PDF),GP/MusicXML 生态对这四曲只有原曲吉他转录与弹唱和弦文本。「同编配结构化源」不存在,非「没找到」(docs/research/2026-11-02-reading-candidate-screening-58.md 线①)。
- **第二环(商业 TAB 引擎)落空**:PhotoScore Ultimate 2020 demo 实测两种形态(站方贴图 PDF/干净位图重打包 PDF)均无法显示四线 TAB 行,杆底符杠读取能力不存在;demo 且封锁 MusicXML 导出(钱闸前置)。SmartScore 64 留观未测,先验低(同代技术同版面假设)。官方声称「4- and 6-string guitar tab」与实际能力的关系就此有实证答案(线②同报告)。
- **升第三环:有工时上限的混合读取+校对**(本 ADR 决策 5 既定顺序)。组件已在库:48 版面切分/49 旋律识别/50 TAB 识别/51 校对台/dolce 互证源(58③:F1 0.84-0.86,失配集中八度点 ±1);57 结论的混合路要点=外部拍位骨架锚定+VLM 只做音位。环的范围与工时上限另立 grill 票定案。
